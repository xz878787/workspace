## Git 
- Head 指针
指向当前所在的分支、所在的版本。
git reset --hard 
          --soft
回退到历史的任意版本

--soft 并不会丢弃工作区的修改， 会去到那个版本进入暂存区之前。    生成的局部修改 text, title 
git restore --staged readme.md 将暂存区的代码移除，工作区
git checkout -- readme.md 丢掉工作区的修改

## Vibe Coding 标准工作流

### 开发前的9个步骤
规划就是一切
#### 三个阶段
- 第一个阶段叫定图纸。
1. 先别去写代码， 先去导需求。
就好像你去跟朋友聊天一样， 可以和claude聊天， 把痛点（足够痛，没解决，有市场）、把目标用户，把使用场景和你理想中的核心功能， 全部讲给AI , 不用追求严谨、信息量， 定完需求。
2. 定完需求后， 把这个需求整理成PRD文档， 你来验收。
让AI 输出一份比较结构化的文档，它中间包括了功能列表、用户流程、页面清单， 每个功能你都要补上一句， 到底做到什么程度才算完成(边界)?
比如: 登录成功， 不是一句话， 要说清楚 登入失败提示什么， 登录成功以后跳转到哪里? (首页、登入前的页面?)
没有验收标准， AI 会写的越来越发散。 
PRD.md
3. 提前订好视觉、和页面框架
找2-3个参考网站， 或者让AI 去生成几种风格的方案。
我们决定， 网页的布局， 页面有哪些内容， 整体使用简约风还是豪华风?
为了后面， 不让AI 一边去写功能(逻辑)， 一边去把UI 推倒重来
- 第二个阶段打地基
4. 明确项目的边界和非功能需求
本地跑? 还是线上公开的？ 用户量多少? 有没有用户数据，支持，
性能和成本有没有上限?
安全、性能、可用性、可用性、成本 这四个非功能性需求不写清楚， 后面一定会返工。
5. 锁定技术栈， 越可验证越好。
适合的就是最好的， React+TS+ TailwindCSS
claude.md 
6. 让AI 出轻量架构草案。
目录架构怎么分层
核心模块有哪些
数据模型长什么样
有哪些组件

- 第三个阶段 立规矩
7. 固化成文档
现在的Agent 和llm 交互都会用一个文件夹， 需要把PRD、设计、架构、当前状态写成项目根目录下的几个文本， 固化下来
PRD.md (产品需求文档)，
ARCH.md (系统架构文档)，
Project.md (当前项目阶段文档)，
...
Design.md 
都是AI的全局上下文， vibe coding 永久约束。
8. 定开发规范和建参考资料文件夹
- 代码规范
- 错误处理
api 接口
restful 规范
可以给一个样本参考
9. 搞好git 和质量闸门。
